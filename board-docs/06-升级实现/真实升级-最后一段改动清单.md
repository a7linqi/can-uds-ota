# 真实升级的最后一段：写使能改动清单

- 日期：2026-11-04
- 针对版本：`Can-learning/ota-core`（含 UART 台架、L4 签名）
- 结论先说：**不是"要写一个 NOR 驱动"，而是"接线 + 填实测参数 + 开闸 + 补两个钩子"**

## 1. 现在为什么升不了级

| 位置 | 现状 | 后果 |
|---|---|---|
| `explorer_reference.c:209` `ota_user_nor_read` | `return -1` | Bootloader 读不出任何镜像 |
| `explorer_reference.c:210` `ota_user_nor_erase_4k` | `return -1` | `0x34` 擦除失败 → `NRC 0x72` |
| `explorer_reference.c:211` `ota_user_nor_page_program` | `return -1` | `0x36` 写不进去 |
| `ota_user_config()` | `storage_verified = 0`（注释写明"ID/EEPROM 读成功也不能授权"） | `storage_ready=0` |
| `ota_user_config()` | `nor_bytes / nor_page_bytes / nor_erase_bytes / eeprom_*` **全 0**（memset 后没填） | 闸门第二重不过 |
| 构建开关 | `OTA_ENABLE_FLASHING=0` | `0x31/0x34/0x36/0x37` 在平台层被 `NRC 0x22` 挡掉 |
| `ota_user_force_loader()` | `return 1` | 永远进 Bootloader，App 起不来 |
| `ota_user_app_healthy()` | `return 0` | App 永远"不健康" → 一定回滚 |
| `explorer_reference.h:14-15` | `#if OTA_ENABLE_FLASHING \|\| OTA_ENABLE_BOOT_HANDOFF \|\| OTA_ENABLE_WATCHDOG` → `#error` | **想开任何一个更新开关都编译不过**（故意的） |

**最后两行不是"忘了实现"**（2026-11-04 查明）：它们是"只读 bring-up 模式"的安全默认值，
而 `explorer_reference.h:14-15` 的 `#error` 把三个更新开关全锁死了，
所以当前 `force_loader()` / `app_healthy()` 是**死代码**——`OTA_ENABLE_BOOT_HANDOFF=0`，
`firmware/bootloader/main.c:51` 的 `#if OTA_ENABLE_BOOT_HANDOFF` 整块不编译。

`force_loader()=1` 是第二道保险：万一有人绕过 `#error` 打开 handoff，
它仍然让 Bootloader 停在 loader，不会跳到空 App（跳过去就是 HardFault）。
`app_healthy()=0` 同理，方向是安全的：宁可多回滚一次，也不会误确认坏镜像。

`stm32_ports.c:16-24` 的闸门要求同时满足：
`board_verified && storage_verified && detected_flash_bytes==1 MiB &&
nor_bytes>=2 MiB && 0<nor_page_bytes<=256 && nor_erase_bytes==4096 &&
erase%page==0 && eeprom_bytes==256 && eeprom_page_bytes==8`

## 3. 改动清单（按依赖顺序）

**顺序陷阱（2026-11-04 实测确认）**：第 4 项不能只把 `OTA_ENABLE_FLASHING` 改成 1——
`explorer_reference.h:14-15` 的 `#error` 会当场拦下编译，报
`Explorer reference bring-up targets are read-only; all update gates must stay off`。
正确顺序是：**先换一份不带这道闸门的真实板级实现（或新增一个独立 target），再开宏**。
同理，第 5、6 项只有在 `OTA_ENABLE_BOOT_HANDOFF=1` 之后才会被编译进去，
在 handoff 关闭时改它们没有任何运行时效果（`bootloader/main.c:51` 的 `#if`）。

| # | 文件 | 改什么 | 验收判据 |
|---|---|---|---|
| 0 | `mdk/explorer_readonly.uvprojx` | 每个 target 加入 `..\\src\\driver\\spi_nor.c` | 链接不再报 `undefined reference to nor_spi_init` |
| 1 | `platform/stm32f407/board/explorer_reference/explorer_reference.c` | 三个 `-1` 桩改为调用 `nor_spi_*`（可直接编译 `w25q128_hal_user.c` 并删掉同名桩） | 上电日志从 `NOR RDID read; fitted chip profile unconfirmed` 变成 `probe ok, 16 MiB`，`22 F187` 仍可读 |
| 2 | 同上 `ota_user_config()` | 填 `nor_bytes=16 MiB`、`nor_page_bytes=256`、`nor_erase_bytes=4096`、`eeprom_bytes=256`、`eeprom_page_bytes=8` | 打印 `storage_ready` 相关字段，逐项与闸门条件对上 |
| 3 | 同上 | `storage_verified` 由"硬编码 0"改为"probe 成功 && JEDEC==0xEF4018 && 擦写时序实测通过" | 单独做一次"擦 1 扇区 + 写 + 读回"自检，通过才置 1 |
| 4 | 板级实现 + 构建参数 | **先拆 `explorer_reference.h:14-15` 的 `#error`**（换真实板级实现 / 新增 target），再 `OTA_ENABLE_FLASHING=1`（台架保持 0） | 能编译通过；`0x34` 不再被 `NRC 0x22` 秒拒，而是按会话/安全依次判 |
| 5 | `ota_user_force_loader()` | 从 `return 1` 改为读 BOOT 引脚或元数据（"有 pending 才进 loader"） | 无 pending 时复位直接进 App（**需 handoff 已开，否则不生效**） |
| 6 | `ota_user_app_healthy()` | 真实实现：App 启动后 commit 一次健康标记（建议 `noinit` RAM 计数 + 元数据），Bootloader 据此决定提交/回滚 | 连续两次掉电重启不触发回滚；人为让 App 挂起则第二次启动回滚（**需 handoff 已开**） |

## 4. 分四个阶段验证，每阶段只放开一点

| 阶段 | 动作 | 判据 |
|---|---|---|
| A 只读 | `ota_user_nor_read` 读 `0x000000` 4 KiB 与 `pass1.bin` 前 4 KiB 比对 | 逐字节一致（不写任何东西） |
| B 单页 | 在下载区擦 1 个 4 KiB 扇区 → 写 256 B → 读回 | 读回 == 写入，且擦除前该扇区非 0xFF |
| C 单块 | 擦 4 KiB + 写满 + 读回 | 一致；记录耗时（擦 ~45 ms / 页 ~0.4 ms） |
| D 整包 | `0x34/0x36/0x37` 下 16 KiB 测试镜像 → `0x31` → `0x11` | `TRIAL→COMMITTED` 或故障时自动回滚 |

## 5. 风险与回滚（都已就绪）

- 外部 NOR 整片有备份：`backups/nor-original/full/20261103_200408_779736/pass1.bin`（sha256 `929af96a…`，器件自算 CRC `0xA4188821`）
- 写坏了大不了重跑 `nor_restore`（已验证：3 块冒烟 + 中断后仍与金标一致）
- EEPROM 快照 `40aff2e9…`，全程未写；恢复元数据时按 128 B 双副本各写一次即可
- **只动前 2 MiB 下载/备份区**，2 MiB 之后是原厂 FAT16 数据（已备份，但没必要碰）

## 7. 已知坑（都会在真机上咬人）

1. **SPI 时钟必须 ≤10 MHz**：当前 PCLK2=84 MHz，分频要 ≥8；示例里有 `spi_configuration_ok()` 逐项校验，别绕过。
2. **CS 要整条命令保持低**：`nor_spi` 靠 `select` 回调控制，别在 `transfer` 里自己拉 CS。
3. **写前必须 WREN + 等 WIP**：漏掉 WREN 的表现是"写成功但内容不变"。
4. **`HAL_SPI_TransmitReceive` 单次别超过 32 B**：示例里按 32 B 分块，直接传大 buffer 会超时。
5. **EEPROM 页只有 8 B**：64 B 的元数据记录要分 8 次页写，跨页会回卷覆盖。
6. **`0x34` 会先擦下载区再回正响应**：擦除失败要在回 `0x74` 之前就报错，否则主机会以为成功。
