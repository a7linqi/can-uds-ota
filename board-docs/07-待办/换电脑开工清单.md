# 换电脑开工清单

> 结论：**可以**。但有 3 个硬约束，不满足就跑不起来。到新机器第一条命令跑
> `python stages/board-lab/tools/check_environment.py`，它会逐项告诉你缺什么。

---

## 硬约束 1：两个路径必须一模一样

```
D:\Project\Can
D:\Project\Can-learning
```

**原因**：72 个文件（脚本、.cmd、md、uvprojx）里硬编码了这两个绝对路径，
不是配置项。路径一改，这些脚本全部指向不存在的目录。

| 寝室电脑情况 | 做法 |
|---|---|
| 有 D 盘 | 直接放进 `D:\Project\`，零改动 |
| 没有 D 盘 | `subst D: <目标父目录>`，再写个 `.cmd` 放进启动目录（subst 重启失效） |

---

## 硬约束 2：CubeProgrammer 装在 `D:\Keil\CubProgram\`

`stages/board-lab/host/nor_restore.py` 的 `--cli` 默认值就是这个路径。
装在别处也能用，但每次调用都要带 `--cli <路径>`，或改那一行默认值。

---

## 硬约束 3：工具链和金标 dump 不在 git 里

| 目录 | 内容 | 体积 | 为什么不在仓库 |
|---|---|---|---|
| `toolchain/` | TinyCC + GNU Arm GCC | 1.5 GB | `.gitignore` 排除，避免仓库爆炸 |
| `backups/` | 16 MiB 金标 dump + 原厂资源 | 177 MB | 含第三方版权内容，不能公开 |

**git clone 拿不到这两样**，必须从本机拷。

---

## 搬运方式：直接拷目录，别 clone

| 源 | 目标 | 体积 |
|---|---|---|
| `D:\Project\Can` | `D:\Project\Can` | 2.8 GB |
| `D:\Project\Can-learning` | `D:\Project\Can-learning` | 98 MB |

用移动硬盘/U 盘整目录拷。`.git` 一起拷过去，历史不丢，两边仍可正常 push。
比「git clone + 重装 1.5 GB 工具链」省事得多。

## 新电脑要装什么

| 软件 | 说明 |
|---|---|
| Python 3.12 | 勾 Add to PATH；再 `pip install pyserial python-can` |
| STM32CubeProgrammer | **必须装在 `D:\Keil\CubProgram\`**，安装包自带 ST-Link 驱动 |
| CH340 驱动 | 板子的 USB 转串口，不装就看不见 COM 口 |
| Git | 推 GitHub 用；SSH key 要在新机器重新配，或改用 https + token |
| WorkBuddy | 才能继续对话 |

**Keil 不用装**：armlink 在本机有 Windows DLL 重定位错误，所有镜像都是 GNU ld 链接的。

## 到新电脑第一条命令

```
python stages/board-lab/tools/check_environment.py
```

检查 6 组，退出码 0 才能动板子：

1. 两个项目路径是否存在、是否被搬到了别的盘符
2. TinyCC / GNU Arm GCC / CubeProgrammer CLI
3. Python ≥3.10 + pyserial + python-can
4. 金标 dump（16 MiB + sha256 + **CRC32 `0xA4188821`**）、三份固件产物
5. ST-Link 是否被 CubeProgrammer 识别；有没有真正的 CH340（蓝牙 COM 口不算）
6. 两个仓库的 git 分支与未提交数

`--skip-hardware` 可以在没插板子时先查软件。

---

## 硬件要带

- 探索者 V3 板子
- ST-Link（SWD 四线：3V3 / GND / SWDIO / SWCLK）
- USB 线 ×2：ST-Link 一根、板子 CH340 一根
- 杜邦线：PA9 / PA10 / GND 接 CH340（UART 台架用）

## 已知坑

1. **COM 口号会变**。本机是 COM9，新机器大概率不同。`uds_gui.py --serial-port COMx`
   和 `transport.py` 都是参数化的，不用改代码。
2. **subst 重启失效**。要持久化就写个 `.cmd` 放 `shell:startup`。
3. **USB 3.0 口有时认不到 ST-Link**。换 USB 2.0 口试。
4. **SWD 只能 1 MHz**。本机 2 MHz 以上直接 `Unable to get core ID`，脚本里已写死 1 MHz。
5. **金标 dump 拷坏了最麻烦**。自检脚本会算 CRC32，不等于 `0xA4188821` 就是拷坏了，
   重新拷一次，别将就。

## 人不在电脑前，用手机推进（WorkBuddy 移动端「连接电脑」）

WorkBuddy 移动端 App 有两个执行模式，选**「连接电脑」**：

| 模式 | 执行在哪 | 能不能用来做这个项目 |
|---|---|---|
| 云端工作 | 云端沙箱 | **不行**——没有 SWD、没有串口、没有那块板子 |
| 连接电脑 | 寝室电脑的桌面端 WorkBuddy | **可以**，和坐在电脑前等价 |

### 前提

| 项 | 要求 |
|---|---|
| 账号 | 手机 App 与电脑端用**同一个微信**登录，否则「连接电脑」连不上 |
| 电脑 | 必须开机、WorkBuddy 桌面端保持运行、**不进入睡眠** |
| 网络 | 电脑能上网即可，不要求和手机在同一个局域网 |

Windows 上要改三处，否则电脑半夜睡了就断线：

1. 电源选项 → 睡眠 → **从不**
2. 电源选项 → 关闭硬盘 → **从不**
3. 笔记本还要设「合上盖子时 → 不采取任何操作」

### 关键：复位不需要人动手

`stages/board-lab/host/nor_restore.py` 用的是 CubeProgrammer 的 `-rst`（软件复位），
**不用按板子上的复位键**。所以 T1 的整片演练可以完全远程发起、远程看进度。

### 远程能干 / 不能干

| 能干 | 不能干 |
|---|---|
| T1 整片演练（发起、看进度、读结果） | 插拔 USB 线、换杜邦线 |
| T2 补丁合入 + 全部主机验证 | 换 CAN 跳线、拨终端电阻 |
| T3–T8 的软件部分、写代码、构建 | 拍丝印照片 |
| 读 evidence、写 journal、推 GitHub | 拔电源做真实断电测试（除非加智能插座） |

### 两条实操建议

1. **配一个兜底**：ToDesk / 向日葵 手机版。App 的「连接电脑」出问题时，
   还能连进桌面点两下；也能用它远程双击那个 `NOR 恢复演练.cmd`。
2. **长任务不要依赖会话保持**。85 分钟的演练，手机上会话断了任务仍在电脑上跑，
   结果落在 `evidence/nor-restore/<时间戳>/`。重连后直接读 `manifest.json`
   和 `events.jsonl`，或用 `python build-temp/drill_status.py` 看进度。

### 唯一真正要人回寝室的

实物丝印拍照（T13）。这件事只能你拿手机对着板子拍，没有替代方案。
