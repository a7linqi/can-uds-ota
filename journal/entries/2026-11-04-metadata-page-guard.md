# 给元数据存储加"真实 EEPROM 页规则"守卫，并用超严模型证明它会变红

- 日期：2026-11-04
- 类型：质量检查 / 防线
- 关键词：`metadata` `at24c02` `page-write` `guard` `false-green`
- 验证等级：主机模型

## 1. 一句话

主机 EEPROM 端口接受任何写入，真芯片不接受跨页写；
把端口换成强制 8 字节页规则的模型后 `metadata_save` 仍然零违规，
再用 4 字节超严模型确认这道守卫**确实会变红**，而不是一个永远绿的摆设。

## 2. 背景与约束

`src/port/host/flash_ram.c` 的 EEPROM 模型只做边界检查，不检查页对齐。
平台层是真的会拒：

```
n > EEPROM_PAGE_SIZE - off % EEPROM_PAGE_SIZE   ->  return -1
```

`metadata_t` 是 64 字节，两份副本间隔 64 字节，一次落盘至少要拆成 8 次单页写。
只要拆边界算错一位，主机套件全绿、板子上第一次 save 就失败。
约束：不改产品源码；不改现有测试；只在 `build-temp` 下建包。

## 3. 现象

把 `strict_page_check.c`（一次性程序）改造成正式测试后，同一份测试文件在三种模型下：

| 模型 | 断言 | 失败 | 违规 |
|---|---|---|---|
| 宽松（等价 host port） | 15 | 0 | 0 |
| 严格 8 字节（真实 AT24C02） | 15 | 0 | 0 |
| 超严 4 字节 | 3 | **12** | **2** |

## 4. 排查过程

| 步骤 | 我怀疑什么 | 做了什么 | 结果 |
|---|---|---|---|
| 1 | 现有测试为什么没抓到跨页 | 读 `src/port/host/flash_ram.c` 的 write | 只查 `off+n<=size`，没有页概念 |
| 2 | 平台层会不会更严 | 读 `platform/stm32f407` 的 eeprom 写实现 | 有 `n>PAGE-off%PAGE` 直接 return -1 |
| 3 | 那 `metadata_save` 到底合不合规 | 用强制页规则的模型驱动 `metadata_save/load` | 15 条断言全过，0 违规 |
| 4 | 这个"全过"能说明什么？ | 把页缩到 4 字节再跑 | 12 条失败、6 次违规 |
| 5 | 守卫本身会不会误伤 | 关掉页检查（`EE_ENFORCE_PAGE=0`）再跑 | 15 条全过，说明断言不依赖模型严格度 |

**转折点**：第 4 步。第 3 步的绿色有两种解释——"实现合规"或"检查无效"。
只有让模型比现实更严格，看它会不会红，才能区分这两者。

## 5. 根因

不是缺陷，是**测试替身失真**：主机端口是真实器件的宽松近似，
用宽松替身测出来的"通过"，对严格器件不构成证据。

这类失真在嵌入式里很常见：RAM 版 flash、无限快的 SPI、永不丢帧的串口。
它们让套件跑得快，也让套件失去发现"时序/页/扇区"类问题的能力。

## 6. 修复

- 文件：`build-temp/metadata-page-package/tests/test_metadata_page.c`（新增）
  - 15 条断言：空存储不误报 / 首存成功 / 回读一致 / 第二次落到另一副本 /
    损坏旧副本后回退到新副本 / 双副本全坏不认 / 确实发生了写 / 违规数=0。
  - 两个编译开关：`EE_ENFORCE_PAGE`（默认 1）、`EE_PAGE_BYTES`（默认 8）。
    开关是为了让守卫**自己可测**，不是为了生产配置。
- 文件：`build-temp/metadata-page-package/tests/test_main.patch`（注册 2 行）
- 文件：`build-temp/metadata-page-package/verify.py`（三档模型一键对比，0.3 秒）
- 备选方案与放弃原因：直接把 host port 改成强制页规则。
  放弃原因：会改动产品仓库的测试端口，且 420 个断电场景跑在上面，
  改模型等于同时改了那批场景的前提；用独立包更安全，也便于维护端取舍。

## 7. 验证

```
python build-temp\metadata-page-package\verify.py
```

| 项 | 期望 | 实际 |
|---|---|---|
| 宽松模型 | 15 断言 0 失败 | 15 / 0 |
| 严格 8 字节（真实 AT24C02） | 15 断言 0 失败 | 15 / 0 |
| 超严 4 字节 | **必须失败** | 3 / 12，违规 6 次 |
| 耗时 | — | 0.30 秒 |

未验证：没上板；模型只覆盖"不跨页"，没建模写周期 5 ms、页写回卷、总线 NAK。

## 8. 学到的东西

1. **测试替身越宽松，绿色越廉价**。用 RAM 模拟 flash、用无延迟模拟 SPI，
   省下的时间最后都会以"板上第一次跑就挂"的形式还回来。
2. 一道检查要能被证明"会红"，否则它的绿没有信息量。
   做法不必复杂：把参数调到比现实更严，看它是否报警。
3. 把一次性验证脚本升级成**带开关的守卫**，成本很低（两个 `#ifndef`），
   收益是把"当时测过"变成"以后一直测"。

## 9. 简历表述

> 发现主机 EEPROM 模型不校验页边界、与真实 AT24C02 行为不一致，
> 新增 15 条断言的页规则守卫测试，并用"超严 4 字节模型"反证守卫确实会失败
> （12 条断言变红、2 次越页），避免了一套永远为绿的假保护。

> 交付形态是可合并包（产品源码零改动），三档模型一键对比 0.3 秒。
