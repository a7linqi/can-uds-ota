# UART 解码器半帧吃掉下一帧（19/300 → 300/300）

- 日期：2026-11-04
- 类型：缺陷
- 关键词：`can-uart` `resync` `crc16` `滑动窗口`
- 验证等级：**主机模型**（TinyCC 编译真实 C）；**未上板验证补丁**

## 1. 一句话

`src/core/can_uart.c` 的解码器在遇到半帧之后，会把**下一帧一起吞掉**，实测 300 次只恢复 19 次。

## 2. 背景与约束

UART 台架把经典 CAN 帧封成 `A5 5A | ver | dlc | id[4] | data[dlc] | crc16` 走串口（CRC-16/CCITT-FALSE）。
约束：`src/core` 属维护端，**我只出补丁和证据，不直接改**。

## 3. 现象

用独立 fuzz 用例（截断一帧后紧跟一个合法帧，300 轮）：

| 实现 | 恢复帧数 |
|---|---|
| 当前 `src/core/can_uart.c` | **19 / 300** |
| 本工程补丁版 | **300 / 300** |

穷举版（dlc 1..8 × 每个切点，共 100 个切点）：

| 实现 | 丢帧 |
|---|---|
| 当前实现 | **92 / 100** |
| 补丁实现 | **0 / 100** |

真机侧同一个缺陷表现为**约 1/3 的 UDS 请求丢失**（见 `2026-11-04-uart-bringup.md`）。

## 4. 排查过程

| 步骤 | 我怀疑什么 | 做了什么 | 结果 |
|---|---|---|---|
| 1 | 校验太弱 | 检查 CRC 覆盖范围与初值 | CRC 正确（向量 `"123456789"`→`0x29B1`） |
| 2 | 缓冲越界 | 看 `len`/`expected` 边界 | 有界，不会越界 |
| 3 | 状态机不重同步 | 单个切点手工推演 | 发现 `DECODER_COLLECT` 只认"自称的 dlc"，没有任何回退余地 |

**转折点**：把"截断帧长度"和"是否丢下一帧"画成表，发现**只有切点刚好等于帧长时才恢复** —— 说明失败时是整块丢弃，而不是逐字节重试。

## 5. 根因

进入 `DECODER_COLLECT` 后，`expected = 8 + dlc` 里的 `dlc` 来自一个**可能根本不是帧头**的字节。
解码器于是继续吞 `expected - len` 个字节（其中包含下一帧的 `A5 5A`），攒够后 CRC 必然失败，`reset()` 把**已经包含下一帧开头**的缓冲整块丢掉。
下一帧的同步头没了，只能等再下一帧的偶发对齐。

## 6. 修复

- 文件：`src/core/can_uart.c`（提案，见 `build-temp/can_uart_resync/can_uart_resync.diff`，48 删 / 107 增）
- 改法：把"攒够就走"换成**对同一块 `buf` 的滑动窗口**——每来一字节从头部反复判定：完整合法帧 → 交付；还差字节 → 等；头部永远不可能成帧 → **丢一个字节再判**。窗口容量 18 字节 = 最大帧长。
- 为什么不"一看到 A5 就 reset"：`A5 5A` 合法出现在 payload 里（用例第 2 组专守这一条），粗暴重同步会误杀好帧。正确顺序是**先验完整帧，再谈重同步**。
- 公共头、线格式、`can_uart_encode` 全部不动；`can_uart_decoder_t` 结构不变。

## 8. 学到的东西

1. **"重同步"是字节流协议的必答题**：任何 `sync + 长度 + CRC` 的格式，都必须能在任意位置失败后继续找下一个 sync，否则一次线路抖动会放大成连续丢帧。
2. **不要用启发式替代解析**：看到 `A5` 就 reset 是错的（payload 可能合法含它）；正确做法是把"能否成帧"的判定做完整，失败就滑动一格。
3. **失败时不要整块丢弃**：缓冲区里可能已经包含下一个帧头，整块丢等于自己把下一帧也杀了。
4. **数字要能现场复算**：`proof.py` 每次都重新编译、重新跑，不存手写数字。

## 9. 简历表述

## 10. 边界与未解决

- 假同步头若自称 18 字节而流里只剩 17 字节，解码器无法推翻它，需等下一个字节；若要"线路空闲立即出帧"，需加 `can_uart_decoder_flush()`（本次不提案，属 API 变更）。
- 是否合并由维护端决定。可提交包在 `build-temp/uart-resync-package/`：补丁（107 增 / 48 删，`git apply --check` 通过）+ `tests/test_uart_fuzz.c` + 注册补丁 + `verify.py`。
- 临时副本跑完整套件（1024 KiB）：旧实现 + 新用例 = **3172 checks / 1 failure**；补丁 + 新用例 = **3173 checks / 0 failures**（420 个断电场景不变，仓库本体未改）。
