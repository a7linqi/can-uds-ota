# 回滚也要交得出证明：凭证重放路径的实机验证

日期：2026-11-05
板子：STM32F407ZGT6 + W25Q128 + AT24C02，UART 台架 115200（COM9）
关联：`stages/board-lab/SECURE_BOOT_EVIDENCE.md`、`journal/entries/2026-11-05-secure-boot-on-silicon.md`

## 1. 一句话

安全启动把凭证放进 App 区尾部之后，回滚路径就多了一道以前不存在的义务——恢复旧镜像时必须连证明一起写回去；
这次在实机上把 TRIAL 计数烧完，回滚产出的 payload 和 96 字节凭证与回滚前**逐字节相同**。

## 2. 背景与约束

- 凭证 = 32 B 容器头 + 64 B Ed25519 签名，位于 `APP_TICKET_OFFSET`（App 区最后 96 字节）。
  选这个位置的理由是「一次擦除同时带走镜像和证明」，代价是 `install()` 必须先读证明再擦、写完 payload 再写证明。
- 安全启动落地后，`image_validate_backup()` 从「只验 CRC」改成「必须验签」，
  `create_backup()` 会把当前凭证的签名抄进备份容器。理由写在代码注释里：
  设备没有私钥，但可以**重放**一份已经存在的证明。
- 这条链只在主机模型里跑过。硬件上从来没验过——而它恰好是「凭证在 App 区尾部」这个设计最脆的地方：
  只要 `install()` 漏写凭证，回滚出来的 App 就是「字节正确但没人背书」，下次启动被判 CORRUPT。
- 用户不在现场时先做了断电实验，之后才轮到这一项。全程远程：ST-Link 和串口都在 USB 上。

## 3. 现象

用 `OTA_EXPLORER_APP_SICK=1` 造一个「能启动、不确认自己」的镜像（44824 B，sha256 `93bf0df84c73…`，
与健康镜像 `47f604c1…` **同为 44824 字节**，只有行为不同），经 UDS 安装为 v16：

```
37 验签 0.34 s → 31 0.29 s → 复位
loader: selecting boot target
loader: handing off to the app at 08010000
app at 08010000: awaiting real health checks
```

之后连续复位，状态按预期推进：

| 启动 | 状态 | attempt | seq |
|---|---|---|---|
| 安装后第 1 次 | TRIAL | 1 | 130 |
| 第 2 次 | TRIAL | 2 | 130 |
| 第 3 次 | TRIAL | 3 | 131 |
| 第 4 次 | **IDLE**（已回滚） | 0 | 133 |

第 4 次启动的横幅里有一段明显的空档：`+009.26s` 选择目标，`+013.65s` 才交棒，中间 **4.39 秒**
——其余每次交棒都在 0.0–0.14 秒。这段就是 RESTORING 在擦 960 KiB 再写回 44 KB。

## 4. 排查过程（弯路都在这里）

**弯路一：第一版三通道监视器什么都没抓到。** 第一次开 5 分钟窗口，562/563 次存活探测全应答、
90 个电压样本全在 3.24–3.25 V、没有第二次冷启动横幅。看上去像「断电没生效」，
其实只是那个窗口里没人动过板子。**空结果不能当成结论**，只能说明监视窗口和操作时间没重叠。

**弯路二：`mode=UR` 不能用来连续采样。** `power_probe.py` 用的是 `mode=UR`（复位下连接），
单次采样没问题，连续采样等于把板子一直按在复位上，量的全是自己的动作。
改成 `mode=HOTPLUG` 前先验了一次：连四次，元数据 `seq` 不变、`role` 仍是 application，
确认它不复位，才敢拿它做 3 秒一次的采样。

**弯路三：我自己的重连逻辑把冷启动横幅吃掉了。** 断电时串口整条消失，
重连路径里 `SerialCanTransport` 重新打开端口后会 `reset_input_buffer()`，
而冷启动横幅正是在那 0.4 秒里打出来的。结果 `banners = 0`。
所以这次断电实验的「冷启动」证据只剩状态 DID，横幅没了——**这是我工具的缺陷，不是板子的**。

**弯路四：`unpowered_spans` 这个名字在撒谎。** 判定条件是「电压读数 > 1.0 V」，
而探针失联时 `voltage` 是 `None`，于是「探针没电」被算成了「电轨没电」。
这次输出 `unpowered=[[485.125, 503.445]]` 实际含义是「**没有读数**」。
如果照着字面写成「实测电压 0 V」，就是把工具的失联冒充成了物理证据。

## 5. 根因

不是缺陷，是一次设计验证：`install()` 的写入顺序是
`读凭证 → 擦 App 区 → 写 payload → 读回校验 → 写凭证`，
而 `create_backup()` 在生成备份容器时把 `flags` 置为 `IMAGE_FLAG_SIGNED` 并附带 64 字节签名。
两处配合才让「重放证明」成立。任何一处漏掉，回滚都会产出一个验不过签的镜像。

## 6. 修复

无需修复。新写了两个台架工具：

- `stages/board-lab/host/power_cycle_watch.py`：一个串口句柄开到底、2 Hz `3E 00` 存活探测、
  3 秒一次 SWD 电压、原始字节流解成横幅文本。端口只开一次是因为关端口本身会通过 CH340 的 DTR/RTS 复位板子。
- `stages/board-lab/host/trial_exhaust.py`：同一条连接内反复发 `11 01` 烧 TRIAL 计数。
  不用开关串口，因为开一次关一次各算一次复位，计数会一次跳 2，attempt 号就跟线上对不上了。

## 7. 验证

**TRIAL 回滚（本次主结果）**

| 对象 | 回滚前 | 回滚后 | 结果 |
|---|---|---|---|
| payload 44824 B | `47f604c13516…` | `47f604c13516…` | 逐字节相同 |
| 96 B 凭证 | `IMG2 v15 44824 0xD6B888DB flags=1 hdrcrc=0x4E85B68B sig=d3294231…` | 同左 | 相同，含签名 |
| 状态 | TRIAL/3 seq 131 | IDLE/0 seq 133 | 回滚完成、pending 清空 |

`role=application` 是旁证：跳转只在 `signed_image_ok()` 通过后发生。

**顺带得到的断电事实（空闲态，不是升级中断）**

- 整条 USB 链路消失 **16.5 秒**（`+481.17s` → `+497.70s`），MCU 停答 `481.175 → 498.601`。
- 塌陷瞬间的最后一次有效电压读数 **2.87 V**（`t=481.80`），随后探针自己失联
  （`No debug probe detected`，485.13–500.39），恢复后 3.24 V。**没有测到 0 V。**
- 恢复后状态与断电前逐字段相同：`IDLE / application / v15 / 44824 B / seq 122`。
  `seq` 没变说明启动路径没写 EEPROM；`role=application` 说明 EEPROM 读成功，
  没有落到 `storage not ready`——也就是 `i2c_bus_clear()` 在真实掉电后仍然管用。

## 8. 学到的东西

- **「重放证明」和「制造证明」的区别**是这套设计成立的关键。设备没有私钥也能证明镜像合法，
  前提是证明在镜像安装时就已经存在、且跟着镜像一起搬。
- **擦除的原子性可以当一致性机制用**：凭证和镜像在同一片擦除区里，
  就不存在「旧凭证配新镜像」这种需要额外协议去防的状态。
- **工具会撒谎**：`unpowered_spans` 把「没读数」写成「没电」、重连路径把横幅吃掉。
  证据链里最容易被污染的一环往往不是被测对象，而是测量工具自己。
- 复位次数要靠协议（`11 01`）而不是靠开关端口来控制，否则计数和事实对不上。

## 9. 简历表述

> 在 STM32F407 上为 UDS/OTA 引导程序设计「镜像 + Ed25519 签名凭证」同区布局，
> 使擦除镜像必然同时作废其证明，从而消除旧凭证配新镜像的窗口；
> 并用自建的三通道台架（2 Hz ISO-TP 存活探测 / SWD 电压采样 / 串口字节流解成启动横幅）
> 在无人在场条件下定位一次真实断电到 16.5 秒窗口，
> 验证 TRIAL 回滚产出的镜像与 96 字节凭证与回滚前逐字节一致。

## 10. 边界与未解决

- **升级中断（擦除/下载/安装中途断电）仍未验证。** 这次只做了空闲态断电：拔电时状态是 IDLE，
  没有任何写操作在进行。要验「升级中断后能恢复」必须有人守在板子旁边按时间点拔电。
- **板载电源开关是否控制电轨仍是 unknown。** 这次用户是**把三根线全拔了**，
  所以「开关一拨就能断电」没有被证明，`BOARD_FACTS.md` 那条保持 unknown。
- **没有 0 V 的实测读数。** 探针与被测对象共用同一条 USB，整条链路断电时探针一起失联。
  想要独立的电压见证，得让 ST-Link 由 PC 供电、目标板单独供电。
- 回滚的断电切点仍然只有主机模型覆盖（79 个切点），实机只跑了「计数正常耗尽」这一条路径。
- 演示公钥对应 seed `00 01 … 1f`，提供篡改检测而非真实授权；Bootloader 自身仍不验签。
