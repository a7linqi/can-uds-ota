# 开发记录

这个目录记的是**怎么做的、为什么这么做、怎么证明的**，不是 API 文档，也不是进度流水。

用途有两个，缺一不可：

1. **复习**：三个月后回来看，能想起当时卡在哪、哪一步是转折点。
2. **简历/面试**：每条记录最后都有"简历表述"，直接可用，且每个数字都能追到证据。

## 怎么用

- 新记录：复制 `TEMPLATE.md` 到 `entries/YYYY-MM-DD-<title>.md`，写完在 `INDEX.md` 加一行。
- 面试前：只看 `INDEX.md` 里 **可写进简历 = Y** 的行，再打开对应记录的第 9 节。
- 记录里的命令应当是**可重跑**的；贴输出时保留真实数字，跑不通就写"未验证"。

## 目录

| 文件 | 作用 |
|---|---|
| `INDEX.md` | 索引表，一行一条 |
| `TEMPLATE.md` | 模板，照抄结构 |
| `entries/` | 正文 |

## 三条规矩

1. **数字只用实测的**，估的写"估算"，没测的写"未实测"。
2. 分清 **主机模型 / 目标构建 / 实机** 三个验证等级，不许混着说。
3. 弯路要留：写清"我先怀疑 X，量了 Y 才发现是 Z"。只写正确路径没有复习价值。

## 和别处文档的分工

| 文档 | 写什么 |
|---|---|
| `journal/`（这里） | 单个功能/缺陷的来龙去脉与证据 |
| `stages/board-lab/STATUS.md` | 当前进度与阻塞（状态表） |
| `CAN_UDS_HANDOFF.md` | 跨工具/跨人的交接摘要 |
| `RESUME_PROJECT_BRIEF.md` | 汇总后的简历素材（从本目录提炼） |
| `ota-core/docs/` | 产品侧设计与说明 |

写记录时不要重复别处的表格，需要时链接过去。
