WHAT THIS PROVES (board-side, runtime, measured)
- "CAN: normal physical 500 kbit/s" is only printed by the
  OTA_EXPLORER_CAN_LOOPBACK=0 branch, i.e. CAN_MODE_NORMAL, not silent loopback.
- "loader diagnostics: request 7E0, response 7E8" is printed only AFTER
  ota_bsp_can_start() returns 0, so HAL_CAN_Init / ConfigFilter / Start /
  ActivateNotification all succeeded. The CAN1 controller is listening.
- hclk_hz = 0x0A037A00 = 168000000 Hz; pclk1_hz = 0x0280DE80 = 42000000 Hz.
  With Prescaler=6, BS1=11TQ, BS2=2TQ: 42 MHz / 6 / (1+11+2) = 500000 bit/s.
  This upgrades the CAN bitrate from "calculated, clock unverified" to measured.
- device_id 0x413 / flash_bytes 0x100000 (1 MiB) = ZG target as built.
- NOR / EEPROM probes healthy; no "EEPROM read failed", no I2C lock-up.

CONCLUSION AT THIS POINT
Firmware, clock, bitrate, driver, power and cabling are all cleared. The board
starts CAN1 in NORMAL mode yet no node answers on the bus. The remaining
unverified link is the physical selection jumper P5 (V3; P11 on older boards):
PA11/PA12 are shared between CAN1_RX/TX and USB FS D-/D+. If P5 is on the USB
side, the MCU CAN_RX never reaches the transceiver and no ACK is generated.
